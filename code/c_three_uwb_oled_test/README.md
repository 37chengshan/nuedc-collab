# 地猛星两路 EWT550 距离与角度测试工程

本工程用于地猛星同时接收两个 EWT550 标签的串口测距文本，完成报文解析、
五帧中值滤波、每路独立标定、双圆定位，并在板载 OLED 上显示两路距离、
比赛径向距离、方位角和定位状态。

这是两路定位测试固件，不包含最终三路定位、拨码认证、迎宾和开锁状态机。
两路结果只能用于测距、标定和角度验证，不能作为最终开锁依据。

## 1. 已验证的数据格式

工程兼容两种已实测的 EWT550 输出：

```text
P,0A00,62cm\r\n
P1,0200,21cm,3dB\r\n
```

- 串口：`115200`、8 数据位、无校验、1 停止位。
- OLED 保留模块原样输出的地址 `0A00`。
- 新格式中的链路编号和 `dB` 信号强度会被接受，当前测试屏主要显示地址、
  距离和解析状态。
- 支持串口分片、连续多帧和异常文本后的自动恢复。
- 支持上位机显示前缀 `re:`。
- 即使串口数据没有换行，也可根据 `cm`、`dB` 或下一帧开头自动切帧。

## 2. 两路接线

只测试接收时，每路只需要连接 EWT 的 `TXD` 和 `GND`。MCU 的发送线可以暂时不接。

| OLED行 | 地猛星接口 | MCU真实接收脚 | EWT550 |
| --- | --- | --- | --- |
| 第1路 | 扩展排针 `A09/GND` | `PA9` | `IO6 → A09`，`GND → GND` |
| 第2路 | 核心板 `UART3 R/G` | `PA25` | `IO6 → R`，`GND → G` |

如需把 MCU 发送线也接上：

| 地猛星发送端 | EWT550 |
| --- | --- |
| `A08`（PA8） | `IO5` |
| `UART3 T`（PA26） | `IO5` |

注意：

1. 调试时可使用 Type-C；正式使用外部稳压 3.3V 时，应断开 Type-C，并按实物供电路径接模块 VCC。
2. 两块 EWT550 与地猛星必须共地。
3. 接入地猛星前，拔掉每块 EWT 板上的 `RXD`、`TXD` USB 串口跳线帽。
4. 不要同时用 Type-C 和地猛星 3.3V 给同一块 EWT 供电。
5. 钥匙端基站继续单独上电，不接地猛星。

## 3. OLED 显示

按同一块 PCB 上已验证可正常显示的小车工程，OLED 使用：

```text
SDA = PB3（B03）
SCL = PB2（B02）
I2C1
```

OLED 已安装在紫色底板上时无需重复接线。

正常显示示例：

```text
D1: 127 D2: 127
R : 100cm
A :  +0deg
0A00 POS:OK
```

状态含义：

- `WAIT`：这一路尚未收到合法测距帧。
- 两路 UART 使用 RX 中断和独立环形缓冲，OLED 刷新期间仍可接收串口数据。
- `OK`：已经收到合法数据，距离为最近五帧中值。
- `BAD`：RX 已经收到原始字节，但暂时没有解析出合法测距帧。
- `LOST`：超过 `500 ms` 没有新合法距离。
- `SYNC`：两路合法距离的时间差超过 `200 ms`。
- `ADDR`：两路收到的钥匙地址不一致。
- `GEOM`：两路距离无法形成有效的双圆交点。

定位坐标按当前实测的两块 EWT550 天线中心距 `250 mm`：

```text
A1 = (-125, +40) mm
A2 = (+125, +40) mm
天线中心距 = 250 mm
径向零点半径 = 300 mm
```

这里必须测量两块模块金色 UWB 天线的中心点，而不是 PCB 边缘。改变实际
安装间距后，必须同步修改上述两个 X 坐标，否则角度会产生系统误差，严重时
会显示 `POS:GEOM`。

方位角定义为 `atan2(x, y)`，正值为面向 FRONT 时的右侧。

## 4. 标定与精度

标定参数位于 `uwb_calibration.c`：

```c
{1000U, 0},  /* 第1路：比例千分数、毫米偏移 */
{1000U, 0},  /* 第2路 */
```

默认值表示不修正。不要只用一两个摆放不一致的数据点直接填写参数。

推荐标定流程：

1. 两块门端天线刚性固定，天线朝向、离地高度和供电方式全程不变。
2. 卷尺测量的是钥匙天线参考点到门锁坐标参考点，不是外壳边缘或 PCB 边缘。
3. 钥匙放在正前方 `0°`，依次测量 `50、100、150、200、300 cm`。
4. 每个点静止采集至少 `100` 帧，分别记录两路中位数，不使用瞬时最新值。
5. 对每一路拟合：

   ```text
   真实距离(mm) = 原始距离(mm) × scale + offset(mm)
   ```

6. 将 `scale × 1000` 四舍五入写入 `scale_permille`，将偏移写入
   `offset_mm`。
7. 再用 `-45°、-30°、-15°、0°、15°、30°、45°` 做独立验证，
   不要用同一批数据既标定又验收。

如果正前方时两路长期存在不同偏差，必须先分别标定两块模块。方位角主要依赖
两路距离差，哪怕单路只偏几厘米，也可能造成明显角度偏差。若固定安装和线性
标定后仍随距离变化，后续再增加分段补偿；最终应增加第三个标签，用三边定位
和残差检查抑制多径。

## 5. 构建

本机直接运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

构建脚本会：

1. 使用 SysConfig 生成 MSPM0G3507 外设配置。
2. 使用 TI Arm Clang 编译和链接。
3. 生成 Intel HEX。

最终烧录文件：

```text
build\c_two_uwb_position_test.hex
```

## 6. 文件说明

- `three_uwb_monitor.syscfg`：两路 UART 和 OLED 的唯一引脚配置源。
- `main.c`：两路 UART 中断缓冲、毫秒时间戳和 OLED 周期刷新。
- `uwb_monitor.c/.h`：EWT550 文本切帧、解析、五帧中值和超时状态。
- `uwb_calibration.c/.h`：两路独立距离比例与偏移标定。
- `uwb_position.c/.h`：双圆定位、径向距离、方位角和 OLED 四行格式。
- `tests/`：真实帧、分片、粘包、两路隔离和显示格式测试。
- `generated/`：SysConfig 自动生成文件，不应手工修改。
- `build/`：`.out`、`.map` 和可烧录 `.hex`。
