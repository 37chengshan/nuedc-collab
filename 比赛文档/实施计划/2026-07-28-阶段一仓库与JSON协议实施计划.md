# 阶段一仓库与 JSON 协议 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 建立可测试的 npm workspace、中文仓库骨架、字节一致的 AI 顶层规则，以及独立 JSON 文件与共享领域动作的协议包，使网页、server、CLI 与 agent 能安全读写任务、问题、想法、事件、成员、资料元数据与设计画布。

**架构：** 根目录只保存工作区编排、共享 TypeScript 配置和文档同步脚本；`packages/protocol` 是唯一的记录与动作 JSON Schema、类型、ID、引用校验、能力校验、路径约束和原子文件读写实现。记录按“一个实体一个文件”落在中文目录中；所有领域客户端经同一动作服务调用，加载时单个损坏文件仅产生结构化隔离信息，不中断其余有效记录。

**技术栈：** Node.js `>=20`、npm workspaces、TypeScript、Ajv 8、Vitest、Node `fs/promises` 与 `crypto`。

## 全局约束

- 本计划仅创建或修改根工作区文件、`比赛管理/**`、`比赛文档/协作规范/**`、本计划列出的中文目录、`packages/protocol/**`、`scripts/**`、根 `README.md`、`AGENTS.md`、`CLAUDE.md` 与 `.gitignore`。
- 不创建或修改 `apps/dashboard/**`、`apps/server/**`、`packages/git-core/**`；不复制比赛资料、不访问远端、不执行推送或破坏性 Git 操作。每个完成任务允许创建本地提交。
- Node.js 版本必须为 `>=20`；包名固定为 `@nuedc/protocol`；根 workspace 固定为 `apps/*` 与 `packages/*`。
- 所有仓库内 JSON 使用 UTF-8、两个空格缩进、末尾换行、英文 `camelCase` 字段；时间使用带时区的 ISO 8601 字符串。
- 任务、问题、想法、事件、成员记录均为 `schemaVersion: 1` 且 Schema 使用 `additionalProperties: false`；未知版本只读报告为错误，不得被写回覆盖。
- 文件名必须等于任务/问题/想法/事件 ID 或成员 GitHub 用户名；保存前必须完成 Schema、文件名、重复 ID、自依赖与引用校验。
- 引用的目标尚未同步到本机时返回警告而非删除、修复或阻断其他记录的读取；同类型但格式错误、循环依赖和本地重复 ID 必须拒绝写入。
- 写入必须先验证，再写同目录临时文件并原子 rename；失败时旧文件保持不变。损坏 JSON 保留在原路径，作为隔离项返回给调用者，不自动移动或删除。
- 任务、问题、想法、事件的一切写动作都必须经 `DomainActionService.execute()`；网页、server、CLI 与 agent 只能适配调用该服务，不能复制所有权、并发、幂等或文件写入逻辑。
- 动作请求的 `idempotencyKey` 必填；所有更新、状态变更、交接和想法提升必须携带记录包装器给出的 `expectedRevision`，创建动作省略该字段。相同键和相同规范化请求重放原结果，不同请求复用同一键返回稳定冲突。
- 动作 JSON 不接收 `actor`。服务始终从 `.本机配置/settings.json` 读取本机 GitHub 用户名并确认该成员 active；适配器仅在受信任运行时注入调用渠道，以执行 agent 专属限制。agent 无权以 DOM 自动化替代领域动作，且不得确认 Git 写操作。
- `AGENTS.md` 与 `CLAUDE.md` 必须由 `比赛文档/协作规范/AI顶层规范.md` 生成，并与该权威正文 UTF-8 字节完全相同。
- `.本机配置/` 与 `.看板缓存/` 必须被 Git 忽略；设置文件的 `confirmGitWrites` 固定为 `true`，首版不可关闭。

import { createHash } from "node:crypto";
import { readFile } from "node:fs/promises";
import { resolve } from "node:path";
import { expect, it } from "vitest";

const root = resolve(import.meta.dirname, "../../..");
const sha256 = (value: Buffer) => createHash("sha256").update(value).digest("hex");

it("权威正文、AGENTS 与 CLAUDE 完全使用同一 UTF-8 字节序列", async () => {
  const [source, agents, claude] = await Promise.all([
    readFile(resolve(root, "比赛文档/协作规范/AI顶层规范.md")),
    readFile(resolve(root, "AGENTS.md")),
    readFile(resolve(root, "CLAUDE.md")),
  ]);
  expect(agents.equals(source)).toBe(true);
  expect(claude.equals(source)).toBe(true);
  expect(sha256(agents)).toBe(sha256(claude));
});
```

export type RecordId = TaskId | IssueId | IdeaId | EventId;
export type TaskId = `T-${string}`;
export type IssueId = `I-${string}`;
export type IdeaId = `A-${string}`;
export type EventId = `E-${string}`;

export interface ProtocolWarning {
  code:
    | "JSON_PARSE_ERROR"
    | "JSON_SCHEMA_ERROR"
    | "JSON_FILE_NAME_MISMATCH"
    | "REFERENCE_NOT_SYNCED"
    | "DESIGN_CONTEXT_REFERENCE_MISSING";
  message: string;
  target: string;
  details?: string[];
}

export interface InvalidJsonFile {
  relativePath: string;
  warning: ProtocolWarning;
}

export interface LoadResult<T> {
  items: T[];
  warnings: ProtocolWarning[];
  invalidFiles: InvalidJsonFile[];
}

export interface PathPolicy {
  readonly repoRoot: string;
  resolveReadable(relativePath: string, allowedRoots: readonly string[]): Promise<string>;
  resolveWritable(relativePath: string, allowedRoots: readonly string[]): Promise<string>;
}

export function createPathPolicy(repoRoot: string): Promise<PathPolicy>;
export function generateTaskId(existing: ReadonlySet<string>, now?: Date): TaskId;
export function generateIssueId(existing: ReadonlySet<string>, now?: Date): IssueId;
export function generateIdeaId(existing: ReadonlySet<string>, now?: Date): IdeaId;
export function generateEventId(existing: ReadonlySet<string>, now?: Date): EventId;
export function readJsonIsolated<T>(options: ReadJsonOptions<T>): Promise<LoadResult<T>>;
export function atomicWriteJson<T>(options: AtomicWriteOptions<T>): Promise<void>;
```

- [ ] **步骤 3：写最小共享动作服务与 CLI**

所有动作输入由 `schemas.ts` 中按稳定 `DomainActionName` 建立的 Ajv Schema 映射校验；`getActionSchema(action)` 与 `validateActionRequest(action, request)` 为 server、CLI 和 agent 适配器提供同一结构定义。创建动作省略 `expectedRevision`；所有更新、`task.setStatus`、交接和 `idea.promoteToTask` 必须携带当前 `RecordEnvelope.revision`。revision 是记录规范化 JSON 字节的 64 位小写 SHA-256，不写回记录，不创建 `recordVersion` 字段。

服务从 `.本机配置/settings.json` 读取 actor，确认相应成员存在且为 `active`；请求 Schema 拒绝 `actor`。`idempotencyKey` 限制为 16—128 个 ASCII `[A-Za-z0-9._:-]` 字符。服务在 `.看板缓存/actions/<sha256(idempotencyKey)>.json` 原子保存 `{ requestHash, result }`，其中 `requestHash` 是动作名、渠道、`expectedRevision` 和 payload 的递归排序 UTF-8 JSON 的 SHA-256。相同键与相同哈希返回原结果并置 `idempotentReplay: true`；同一键不同哈希返回 `IDEMPOTENCY_KEY_REUSED`；单仓库异步写锁覆盖收据读取、revision 比对、写入和收据保存。

读取门面返回 `RecordEnvelope<T>`：`data` 是原始记录，`relativePath` 为仓库相对路径，`revision` 为规范化 JSON 哈希。Idea 列表额外在包装器上返回 `effectiveState`：任何任务的 `sourceIdeaId` 等于 Idea ID 时为 `converted`，否则 `status` 映射为 `open | discarded`。该派生字段不得写入 Idea JSON。

动作名称和执行语义固定如下：

| 动作 | 结果与所有权规则 |
|---|---|
| `task.create` | active actor 创建独立任务文件；owner 只能省略或等于 actor。 |
| `task.update` | 未认领任务可由 active actor 认领；已认领任务仅 owner 可更新。 |
| `task.setStatus` | 仅 owner；`to: done` 时两个验收数组必须集合相等，并由系统追加 `statusChange` 事件。 |
| `task.handoff` | 仅当前 owner；目标必须 active，并由系统追加 `handoff` 事件。 |
| `issue.create`、`issue.update`、`issue.handoff` | 与任务相同的 active/owner/交接规则；交接由系统追加 `handoff` 事件。 |
| `event.append` | 任一 active actor 可追加，服务强制 `actor` 为本机成员；所有外部渠道仅允许 `comment | decision | testResult`，`statusChange | handoff` 仅由系统动作生成。 |
| `idea.create` | 服务生成 A-ID，强制 `author` 为 actor；owner 只能省略或等于 actor。 |
| `idea.update` | 未认领时仅 author 可修改或认领；认领后仅 owner 可修改；author 不可变。 |
| `idea.promoteToTask` | 仅 Idea author 或 owner；创建一项 `sourceIdeaId` 等于该 Idea ID 的任务，不改写 Idea；已有来源任务时返回该任务而不再创建。 |
| `member.update`、`settings.update` | 仅供后续本地 API 的明确成员/设置流程调用；仍通过同一 Schema、幂等和原子写入层。 |

稳定错误码至少为 `ACTION_VALIDATION_FAILED`、`ACTION_NOT_SUPPORTED`、`STALE_ENTITY`、`IDEMPOTENCY_KEY_REUSED`、`OWNER_MISMATCH`、`INACTIVE_MEMBER`、`PROMOTED_TASK_ALREADY_EXISTS`。`STALE_ENTITY` 结果携带当前记录包装器；`PROMOTED_TASK_ALREADY_EXISTS` 作为成功的可恢复结果携带首次任务包装器和中文说明，不重复写入。

`agent-cli.ts` 实现以下无浏览器、无服务进程依赖的命令，stdout 只输出 `CapabilityDocument` 或 `DomainActionResult` JSON，失败使用非零退出码，诊断写 stderr 并脱敏：
