# 阶段二 Git 与本地 API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在不触碰阶段一职责的前提下，交付受限 Git 状态机、真实本地 Git 集成测试、localhost API、agent-native 领域动作、资料与总体设计扫描、生产静态托管和安全测试。

**架构：** `packages/git-core` 仅执行固定模板的 Git 查询与确认式写操作，并产生三轴状态。`apps/server` 绑定回环地址，组合 Git 核心、阶段一提供的记录仓储适配器、统一的 `DomainActionService` 和资料/设计扫描器；HTTP 与本机 CLI 均调用同一个动作服务。生产模式只读托管已构建的 `apps/dashboard/dist`，不创建或编辑该目录。

**技术栈：** Node.js `>=20`、TypeScript、Node `http`、Ajv、Vitest、Playwright、临时 bare Git remote 与三个本地 clone。

## 全局约束

- 本计划仅创建或修改 `packages/git-core/**`、`apps/server/**`，以及这两个目录下的测试与 fixture。
- 不创建、修改或审阅本计划范围外的文件；生产静态托管仅以 `apps/dashboard/dist` 为只读输入。
- `apps/server` 只把 `apps/dashboard/dist` 视为生产静态资源根；缺失该目录时 API 仍可运行，页面请求返回明确的 503 中文说明。
- 服务器只绑定 `127.0.0.1`；`::1` 必须由启动参数显式启用。
- 写 Git 请求必须携带 `X-Local-Auth`、`confirmed: true` 与确认页记录的预期状态；状态改变时返回 `409 STALE_GIT_STATE` 且不执行写操作。
- Git 子进程必须使用 `spawn` 或 `execFile`、`shell: false`、固定命令模板、`GIT_TERMINAL_PROMPT=0`、空 hooks 目录、输出上限与超时。
- 禁止 `reset`、`clean`、`rebase`、`checkout`、`switch`、`submodule`、任意 `config`、任意远端/分支参数和 force push。
- 所有客户端路径均先规范化并做真实路径包含检查；拒绝绝对路径、`..`、符号链接逃逸、未允许扩展名和 `.meta.json` 作为内容读取目标。
- `GET /api/materials` 与 `GET /api/design` 的顶层响应必须都返回 `warnings: Array<{ code, message, target }>`，没有警告时为 `[]`。
- 任务、问题、事件和想法的所有写入必须经过 `DomainActionService`；HTTP 路由、agent 端点和 CLI 均不得直接写记录文件。
- 每个领域动作请求体均要求 `idempotencyKey`；同键、同动作、同规范化请求返回已保存响应，同键但请求不同返回 `409 IDEMPOTENCY_KEY_REUSED`。
- 创建动作省略 `expectedRevision`；所有更新、状态变更、交接和想法提升必须携带记录包装器中的 64 位小写 SHA-256 revision。revision 不一致返回 `409 STALE_ENTITY` 与最新记录包装器，不写入记录。
- 当前本机成员必须是 active member；请求不接受 `actor`。任务、问题和已认领想法的修改或交接必须由对应 owner 发起；未认领想法只允许 author 修改或认领。
- 动作成功与失败响应均返回稳定错误码、结构化实体或错误、`idempotencyKey`、`warnings` 和 `nextActions`；`nextActions` 只能引用能力端点声明的动作或标注为 human 的 Git 确认建议。
- 通用动作集合永远不含 Git；CLI 只映射动作协议，绝不调用 `GitCore.pullFastForward()`、`commitSelected()` 或 `push()`。
- 不访问真实 GitHub、不使用真实凭据；Git 集成测试只使用临时目录和本机 HTTP 401 服务。

写操作固定顺序：

1. 通过 `AsyncGitLock.run(repoRoot, operation)` 获取互斥锁。
2. 重读 `GitState`；任何预期 HEAD、远端 HEAD 或选中文件摘要变化均抛出 `STALE_GIT_STATE`。
3. `pullFastForward()` 只在 `clean + behind + online` 时执行 `git merge --ff-only origin/main`。
4. `commitSelected()` 校验 1—200 个去重相对路径、1—500 个 Unicode 字符消息和空 index；备份 `.git/index` 到 `.看板缓存`，固定执行 `git add -- <files>`，验证暂存路径集合与 index blob 摘要，再执行 `git commit -m <message>`；任一失败恢复 index。
5. `push()` 先固定 fetch，再验证 `clean + ahead + online`、远端未领先和非分叉，最后仅执行 `git push origin HEAD:main`。

`DomainActionService.execute()` 固定遵循下表：

| 动作 | revision | 授权与副作用 |
|---|---:|---|
| `task.create` | 否 | actor 必须 active；新任务 owner 为 actor。 |
| `task.update` | 是 | actor 必须为任务 owner；不得通过该动作改变 status 或 owner。 |
| `task.setStatus` | 是 | actor 必须为 owner；`to: done` 时两组验收条件集合必须相等。 |
| `task.handoff` | 是 | 当前 owner 把任务交给另一 active member，并自动追加 `handoff` 事件。 |
| `issue.create` | 否 | actor 必须 active；新问题 owner 为 actor。 |
| `issue.update` | 是 | actor 必须为问题 owner。 |
| `issue.handoff` | 是 | 当前 owner 交给另一 active member，并自动追加 `handoff` 事件。 |
| `event.append` | 否 | actor 必须 active；仅允许 `comment`、`decision`、`testResult`，目标可为 task、issue 或 idea。 |
| `idea.create` | 否 | actor 必须 active；`author` 固定为 actor，owner 可省略。 |
| `idea.update` | 是 | 已认领时仅 owner；未认领时仅 author，可将 owner 设为 actor 完成认领。 |
| `idea.promoteToTask` | 是 | actor 必须为 idea owner；只创建 `sourceIdeaId` 为 idea ID 的任务，不写 idea；已存在时返回首个任务及 `PROMOTED_TASK_ALREADY_EXISTS` 警告。 |
| `member.update` | 是 | actor 必须 active，且只能更新自己的成员记录。 |
| `settings.update` | 是 | actor 必须 active；只传递规范允许的本机设置字段。 |

`POST /api/actions/:action` 接收 `ActionRequest` JSON 和 `X-Local-Auth`，将 `:action` 与注册表比对后调用 `DomainActionService.execute()`；通用动作列表不含任何 `git.*`。资源写端点 `POST /api/tasks`、`PUT /api/tasks/:id`、`POST /api/issues`、`PUT /api/issues/:id`、`POST /api/ideas`、`PUT /api/ideas/:id`、`POST /api/ideas/:id/promote`、`POST /api/events`、`PUT /api/members/:githubUsername`、`PUT /api/settings` 均只负责把路径参数合并到 payload 后调用同一服务。

`GET /api/capabilities` 返回 `protocolVersion: 1`、本机 actor、13 个动作的中文说明、revision/幂等要求及 `schemaRef`，并固定返回 `domAutomationAllowed: false`、`directFileMutationAllowed: false`、`gitConfirmationRequired: true`。成功响应严格使用 `ActionSuccess`；`nextActions` 可以建议 `git.commit`、`git.pull` 或 `git.push`，但其 `confirmationPolicy` 必须为 `human`，且不执行 Git。

本机 CLI 只调用 `DomainActionService`：

```text

npm run agent -- action task.create --input <payload.json>
npm run agent -- action task.setStatus --input <payload.json>
npm run agent -- action issue.create --input <payload.json>
npm run agent -- action idea.promoteToTask --input <payload.json>
```

`cli-actions.ts` 读取完整 `ActionRequest` JSON，解析本机 actor，调用同一服务；stdout 只输出结构化 JSON，失败使用非零退出码，诊断写 stderr 并脱敏。任何不在 13 个动作中的名称（包括 `git.*`）返回 `ACTION_NOT_SUPPORTED`，CLI 不调用 Git 核心写方法。

- [ ] **步骤 3：写最小 Schema 与扫描实现**

`content-models.ts` 使用 Ajv 严格校验以下 `.meta.json` 字段：`id`、`title`、`type`、`sourceLabel`、`modules`、`license`、`verificationStatus` 必填；`versionLabel` 可选且去除首尾空白后为 1—100 Unicode 字符；对象禁止未知字段。扫描器不信任元数据提供的路径、时间、大小或哈希，而是由服务端从匹配资料文件计算。

`scanMaterials()` 递归扫描 `参考资料` 与 `比赛文档/官方通知`，跳过 `.meta.json`、隐藏文件和不允许扩展名；对每个内容文件查找同目录同 basename 的 `<basename>.meta.json`。有效元数据生成 `MaterialItem`；缺失或损坏元数据时生成确定性 `id` `unverified-${sha256.slice(0, 16)}`、`verificationStatus: "pending"`、`sourceLabel: "未提供元数据"`、`modules: []`，并分别产生 `MATERIAL_METADATA_MISSING` 或 `MATERIAL_METADATA_INVALID`。`previewMode` 由已核验的实际扩展名和 magic bytes 推导，不由元数据指定。

`scanDesign()` 递归扫描 `比赛设计/赛题分析`、`总体方案`、`接口约定`、`测试记录`、`可视化页面`，目录名映射为精确 `DesignCategory`；只产出 `.md`、`.html`、`.json` 三种格式，排除固定画布文件。固定读取 `比赛设计/总体方案/系统画布.json`：不存在时 `canvas: null`；存在时校验节点 ID 唯一、`x/y` 在 `0..100`、边的 `source/target` 都引用现有节点。画布同级 `context` 对象只接受 `issueIds`、`materialIds`、`decisionEventIds` 数组；任何缺失引用产生 `DESIGN_CONTEXT_REFERENCE_MISSING` 警告，不阻断响应。

`GET /api/materials/content` 与 `GET /api/design/content` 都拒绝 `.meta.json` 路径；仅允许 Markdown、JSON、HTML、PNG、JPEG、WebP、PDF 的规格上限和 magic bytes；HTML 添加 `Content-Security-Policy: sandbox` 与 `X-Content-Type-Options: nosniff`。
