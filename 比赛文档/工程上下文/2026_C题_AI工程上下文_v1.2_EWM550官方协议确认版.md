# 0. 本版本更新结论

本版本基于：

1. 2026 电赛 C 题官方题目；
2. 亿佰特《EWT550-7G9T10SP 产品规格书》v2.1；
3. 已购买 4 个 EWM550/EWT550 相关 UWB 设备；
4. 已确认的 1 基站对多标签 TWR 工作方式。

相比 v1.1，最重要的更新是：

- **正式将“数字钥匙 = UWB 基站（主机）”作为首选拓扑。**
- **智能门锁 = 3 个固定 UWB 标签（从机） + TI 地猛星。**
- 官方资料已经明确给出 **1 基站 + 3 标签**配置方法。
- 官方资料明确：**标签端 UART 也输出自身到主机的距离。**
- 因此门锁端 3 个标签可以分别通过 UART 给地猛星提供 `d1/d2/d3`，无需钥匙再用蓝牙/WiFi回传距离。
- 标签端数据包中包含**主机地址**，可直接作为数字钥匙 ID 的来源。
- 抗多径不能默认依赖 SNR，因为官方格式中 **SNR 只明确出现在基站端输出**；门锁标签端标准输出示例只有“主机地址 + 距离”。
- EWT550 是测试底板，尺寸约 **30 × 58 mm**；EWM550 是实际 UWB 模组。到货后必须确认购买的是裸模组还是带 EWT 测试底板版本。

除非实测证明该首选拓扑无法满足精度，否则后续 AI 不应再重新讨论完全不同的主架构。

# 5. 600 mm 圆柱边界是径向距离零点

这是本题非常重要的测试定义。

题目规定：

**直径 600 mm 的圆柱体边界，是径向距离的零点。**

不是：

- 门锁中心
- 地猛星位置
- 任意 UWB 节点
- 任意天线位置

如果内部统一以圆柱中心为：

`O = (0,0)`

圆柱半径：

`R0 = 0.30 m`

定位得到钥匙参考点：

`P = (x,y)`

中心距离：

`R = sqrt(x^2 + y^2)`

理想圆形边界下：

`r = R - 0.30 m`

其中 `r` 才是用于：

- 1 m 开锁边界
- 2 m 迎宾边界
- OLED 距离显示

的比赛径向距离。

机械零点和程序零点必须从第一天统一。

# 10. 为什么“钥匙做基站，门锁做标签”

名称虽然反直觉，但这是当前最合理的协议映射。

EWM/EWT 的“基站/标签”是：

**协议角色**

并不等于物理世界里“固定/移动”。

官方 1 对多机制是：

一个基站轮询多个标签。

我们需要同一把钥匙到三个固定参考点的距离：

- d1
- d2
- d3

因此最自然的配置就是：

**移动钥匙 = 主机**

**三个固定参考点 = 从机**

这样一个主机天然轮询三个门锁节点。

# 11. 官方数据包已确认

## 11.1 基站端

官方示例：

`P0,AA00,10cm,20dB\r\n`

含义：

- `P0`：从机序号
- `AA00`：从机地址
- `10cm`：距离
- `20dB`：SNR

因此：

**基站端可以看到每个标签的地址、距离、SNR。**

但本方案的基站位于数字钥匙中。

基础方案不依赖钥匙侧串口数据。

---

## 11.2 标签端

官方示例：

`P,1111,10cm\r\n`

含义：

- `P`：包头
- `1111`：主机地址
- `10cm`：本标签到主机的距离

这条信息非常关键。

说明：

**每个门锁标签自己的 UART 都可以直接输出“数字钥匙主机地址 + 当前距离”。**

所以门锁地猛星不需要钥匙额外通过 BLE/WiFi 回传距离。

# 12. 三路 UART 数据结构

假设钥匙主机地址：

`000B`

三个门锁标签 UART 可能分别输出：

```text
A1:
P,000B,143cm

A2:
P,000B,162cm

A3:
P,000B,151cm
```

由于：

- A1 UART 物理接固定串口 1
- A2 UART 物理接固定串口 2
- A3 UART 物理接固定串口 3

因此标签输出包不需要携带标签自身地址。

软件根据：

**UART 通道**

就知道这一距离属于：

- A1
- A2
- A3

# 13. 数字钥匙 ID 方案

题目需要：

**4 bit ID**

建议直接利用：

**UWB 主机 SRCADDR 的低 4 bit**

例如数字钥匙 ID：

`1011`

十六进制：

`B`

则钥匙主机地址设为：

`000B`

门锁标签收到：

`P,000B,xxxcm`

地猛星提取：

`0x000B & 0x000F = 0xB`

得到：

`1011`

然后与 4 位拨码比较。

---

# 14. ID 验证流程

例如拨码：

`1011`

则：

`expected_id = 0xB`

收到：

`P,000B,143cm`

解析：

`key_id = 0xB`

比较：

```text
key_id == expected_id
        ↓
      PASS
```

如果拨码改为：

`0101`

则：

```text
key_id = 1011
expected = 0101
        ↓
      FAIL
```

UWB 仍然可以继续测距和检测钥匙。

但：

**认证失败时禁止开锁和迎宾。**

---

# 15. 三个标签之间的 ID 一致性

每条标签 UART 都包含主机地址。

一次定位时：

A1、A2、A3 的主机地址应该一致。

例如：

```text
A1 → 000B
A2 → 000B
A3 → 000B
```

才允许组合成一个完整位置帧。

如果出现：

```text
A1 → 000B
A2 → 000B
A3 → 0007
```

则：

- 本组三距离不能直接融合
- 标记为不同钥匙 / 数据异常
- 禁止因此开锁

---

# 16. 三路距离的时间同步

三个标签不是绝对同时测距。

主机是按轮询方式依次完成 TWR。

因此地猛星不能简单拿：

“每一路最后一次距离”

永久混在一起。

每条 UART 数据必须记录：

- `key_id`
- `distance`
- `timestamp`

只有三个样本满足：

- key_id 一致
- 时间差足够小
- 全部未超时

才组成：

`UwbFrame`

时间窗口具体数值：

**必须根据模块实际轮询频率测试决定。**

第一版可从几十到约 100 ms 的量级测试，不要在未实测前写死。

# 23. 定位算法

三个 Anchor：

`Ai = (xi, yi)`

钥匙：

`P = (x,y)`

三个距离：

`di`

满足：

`(x-xi)^2 + (y-yi)^2 = di^2`

优先：

**三边定位 + 最小二乘**

后续可升级：

**加权最小二乘**

---

# 24. 距离与角度

得到：

`P = (x,y)`

中心距离：

`R = sqrt(x^2 + y^2)`

比赛径向距离：

`r = R - 0.30`

方位角：

`alpha = atan2(x, y)`

定义：

- 正前方 = 0°
- 左侧 = 负
- 右侧 = 正

- 从机地址

响应不能太慢。

# 28. 三边几何残差

解出位置：

`P(x,y)`

重新计算理论距离：

`d1_hat`
`d2_hat`
`d3_hat`

残差：

`ei = abs(di - di_hat)`

某一路残差异常大：

- 本帧降权
- 或剔除该路
- 尝试 2 路降级定位
- 禁止单帧异常触发开锁

- `AUTH_FAIL`

  ↓

# 38. UART 解析器

标签标准格式：

`P,1111,10cm\r\n`

解析逻辑：

1. 找到行结束；
2. 判断包头 `P`；
3. 读取主机地址；
4. 读取距离数值；
5. 单位 `cm → m`；
6. 保存本 UART 对应 Anchor 的数据；
7. 记录时间戳。

不要直接在串口中断里做三边定位。

中断 / DMA 只负责：

- 收数据
- 分包
- 入队

定位放在主循环 / 定时任务。

# 48. 最终系统定义

本项目当前冻结方案：

**使用 1 个 EWM/EWT550 UWB 主机作为电池供电数字钥匙，使用 3 个 EWM/EWT550 UWB 标签作为智能门锁内部的固定测距节点；三个标签分别通过 UART 把“钥匙主机地址 + 距离”送给 TI 地猛星，地猛星以主机地址低 4 bit 作为数字钥匙身份 ID，并利用三组距离进行二维定位，计算比赛定义的径向距离和方位角，再完成 4 位拨码身份验证、1 m/2 m 区域状态机、OLED 显示、声光迎宾和开闭锁 LED 控制。**

机械方面：

- 数字钥匙 ≤ 120 × 80 × 40 mm
- 智能门锁 ≤ 直径 600 mm × 高 300 mm
- 600 mm 圆柱边界为径向距离零点
- OLED 位于门锁背面
- 三个 UWB 固定节点采用大基线非共线布置
- 天线参考点坐标装配后实测
- 正前方明确标记

这是后续硬件、软件、3D 结构和测试工作的统一基准。
