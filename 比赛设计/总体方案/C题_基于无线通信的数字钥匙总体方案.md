## 1. 当前结论与状态口径

当前首选方案是：

**电池供电数字钥匙使用 1 个 EWM/EWT550 主机，智能门锁使用 3 个固定 EWM/EWT550 标签和 1 块 MSPM0G3507 主控；三个标签分别把“钥匙主机地址 + 距离”送入主控，主控完成二维定位、4 bit ID 验证、区域状态机、背面显示和声光锁态。**

首版范围冻结如下：

- 数字钥匙不设置 MCU，由电池、一键电源和 UWB 主机组成。
- 门锁背面显示使用 `1.77 英寸 ST7735S`。
- 红绿 LED 模拟开锁和闭锁，不增加舵机或电磁铁。
- 身份验证按题目实现 `4 bit ID + 连续帧/超时/故障锁定`，不增加密码学认证。
- 当前两站固件已切换到四位拨码直读后端；物理位序从左到右为
  `bit3、bit2、bit1、bit0`，ON 接地并解释为 `1`。

## 4. 总体系统链路

```text
数字钥匙
电池 → 一键电源 → EWM/EWT550 Initiator
                      │
                      │ 1 对 3 TWR，持续发送主机地址
                      ↓
智能门锁
Responder A1 ─UART─┐
Responder A2 ─UART─┼→ MSPM0G3507
Responder A3 ─UART─┘      │
                          ├→ 地址一致性与时间窗
                          ├→ 三边定位 / 最小二乘
                          ├→ r、α 与残差
4 位拨码 ────────────────→ ID 验证
                          ├→ 区域状态机
                          ├→ 背面 ST7735S
                          ├→ 迎宾 LED / 蜂鸣器
                          └→ 红绿开闭锁 LED
```

“基站”和“标签”是协议角色，不代表物理上固定或移动。移动钥匙作为 Initiator，三个门锁节点作为 Responder，目的是让三个固定节点各自获得到同一钥匙的距离。

## 5. UWB 协议基线

仓库同时保留厂商站下载的 v2.0 和用户在 2026-07-30 提供的 v2.1。v2.1 修订历史注明 `2026-03-20 修正错误描述`，给出以下能力：

- 最多 `1 对 5` 双向测距。
- `1 基站 + 3 标签` 配置示例。
- 基站示例：`P0,AA00,10cm,20dB\r\n`。
- 标签示例：`P,1111,10cm\r\n`，其中地址是主机地址。

本项目因此把每个 UART 物理通道绑定到一个固定节点：

```text
UART_A1 → Anchor A1 的 key_addr、distance、timestamp
UART_A2 → Anchor A2 的 key_addr、distance、timestamp
UART_A3 → Anchor A3 的 key_addr、distance、timestamp
```

融合条件：

- 三路 `key_addr` 一致。
- 三路样本都未超时。
- 最大时间差位于实测确定的融合窗口内。
- 格式、单位和距离范围有效。

标签标准示例没有 SNR，因此生产协议不能把“必须收到 SNR”作为唯一
可用路径。当前两站固件保留今天数据验证过的 SNR 门，同时增加受限
兼容路径：仅当两路都没有 SNR、两路都携带同一个有效
`key_addr` 时，才按样本数、MAD、特征差、原型距离、邻域跨度和连续
稳定性判断质量；只缺一路 SNR、缺少钥匙地址或地址不一致仍闭锁。

厂商文档中 `RESPONDERR_NUM` 与 `RESPONDER_NUM` 拼写不一致，配置时优先使用厂家上位机、模块查询结果和实机响应。

2026-07-31 两站采集使用的 `P0,0100,...`、`P1,0200,...` 是多链路
站点/目标链路地址，不能把 `0100/0200` 的低 4 bit 当成钥匙 ID。
两站候选固件已将 `station_addr` 与 `key_addr` 分离：

- `P0/P1` 帧只有站点地址时可以测距，但 `key_id_valid=false`，永不授权。
- 固定站输出 `P,1111,...` 时，`1111` 才作为钥匙地址。
- 也可使用 `STATION=0100,KEY=1111,...` 同时显式携带两类地址。
- 串口工具附加的 `re:` / `RE:` 前缀由固件在解析前剥离。
- 两路钥匙地址不一致或发生切换时，立即清空窗口、稳定性历史和上一可信结果。

## 6. ID 与安全状态机

只有经过协议语义确认的钥匙主机地址低 4 bit 才作为候选 ID：

```text
key_id = key_addr & 0x0F
expected_id = 4 位拨码值
```

仅当两路钥匙地址一致、`key_id_valid=true`、距离质量为 `HIGH` 且
`key_id == expected_id` 时，才允许进入迎宾或开锁状态。缺失钥匙
地址时保持闭锁，但不把站点地址或默认零值伪装成身份。

4 位拨码必须支持运行时手动修改门锁身份 ID。建议从左到右固定为 `bit3、bit2、bit1、bit0`，拨向显示器方向表示 `ON=1`；固件对拨码做不少于 20 ms 消抖，并在稳定变化后立即更新 `expected_id`，不要求断电重启。显示器必须同时显示：

```text
SET ID: 0xN       ← 当前拨码值
KEY ID: 0xN       ← 当前收到的钥匙 ID
AUTH: MATCH/FAIL  ← 是否等于修改后的 SET ID
LOCK: LOCK/OPEN
```

验收时先让某钥匙 ID 匹配，再手动改变任意一位拨码，系统应在显示稳定后把同一钥匙判为 `FAIL` 并保持锁定；将拨码改回匹配值后才允许重新进入迎宾/开锁状态。这样才能完整证明“手动修改身份 ID、按修改后的身份识别并显示识别结果”，不能只显示收到的钥匙 ID。

### 6.1 保留的临时四按键输入后端

源码仍保留四个独立按键分别翻转 `bit3、bit2、bit1、bit0` 的后端，
用于没有拨码时的临时测试：

- GPIO 使用内部上拉，按下为低电平。
- 每次完成一次稳定按下后执行 `expected_id ^= (1U << bit)`。
- 初始消抖为 `30 ms`，必须检测到释放后才允许下一次翻转，长按不重复。
- 上电恢复 `0000`，暂不写入 Flash。
- 应用层仅调用 `id_input_get_value()` 和 `id_input_process(now_ms)`。

当前 `main.c` 不再使用该后端。

### 6.2 当前四位拨码直读

当前主程序使用四位稳定电平直读：

```text
bit0 = PA28
bit1 = PA31
bit2 = PA13
bit3 = PA16
```

GPIO 内部上拉，`ON` 时接地并由软件取反为 `1`。上电首次读取立即
生效，运行中变化稳定 `30 ms` 后更新。全部 OFF 时密码为
`0000 / 0x0`；例如 `0xA / 1010` 的拨法为 bit3 ON、bit2 OFF、
bit1 ON、bit0 OFF。

```text
NO_KEY
  ├─ 收到格式错误/超时 → 保持锁定
  └─ 收到有效地址
       ├─ ID 不匹配 → AUTH_FAIL → 保持锁定
       └─ ID 匹配
            ├─ r > 2 m       → SENSING
            ├─ 1 m < r ≤ 2 m → WELCOME
            └─ r ≤ 1 m       → UNLOCKED
```

降级策略：

- 3 路有效：最小二乘定位，并检查几何残差。
- 2 路有效：只在几何条件允许时求两个候选交点，选择前方候选并降低置信度。
- 1 路有效：只显示 ID 和单路距离；不得输出可靠方位角，保持锁定。
- 0 路有效或超时：回到 `NO_KEY`，关闭迎宾并保持锁定。

## 7. 坐标、径向零点与定位

统一坐标：

- 圆柱中心为 `O=(0,0)`。
- `+y` 为 `FRONT`。
- `+x` 为面向 FRONT 时的右侧。
- 圆柱半径 `R0=0.30 m`。

钥匙定位点为 `P=(x,y)`，则：

```text
R = sqrt(x² + y²)
r = R - 0.30 m
α = atan2(x, y)
```

`r` 才是用于 1 m、2 m 边界和 OLED 显示的比赛径向距离。程序不能把门锁中心、主控板或任意单个天线作为径向零点。

v0.4 紧凑型外壳的名义锚点仅作为结构起点：

```text
A1 = (-114, +40, 48) mm
A2 = (+114, +40, 48) mm
A3 = (0, -88, 48) mm
```

正式算法必须使用装配后的实测天线参考点坐标和高度。三枚门锁天线与钥匙天线参考点应尽量等高，明显高度差需纳入三维误差分析或机械修正。

### 8.1 2026-07-31 两站 145 mm 实测候选分支

本节只记录 2026-07-31 现场两站数据的当前候选实现，不替代第 4 节的一主三从正式拓扑，也不包含后续第三、第四模块标定。

数据来源固定为：

```text
sessionId = 2026-07-31T17-42-29-827Z
```

两站天线参考点按用户实测值冻结为：

```text
右站 device1 / 0100 = (+72.5, 0) mm
左站 device2 / 0200 = (-72.5, 0) mm
基线 B = 145 mm
FRONT = y >= 0
比赛径向距离 = sqrt(x² + y²) - 300 mm
```

标签审计规则：

1. 1 m 角度组（包含本轮 0.8～1.2 m 边界辅助点）标题正负全部互换。
2. 第一个 `1m 30度` 采集实际为 15°，修正后的真值为 `-15°`。
3. 两个正向 `2m 30度` 采集整组废弃。
4. `continuous-field-site...` 仅保留作现场连续记录，不进入训练。

审计后为 `56` 组有效采集、`43` 个独立物理点。完整原型清单和生成参数保存在：

```text
code/c_digital_key_lock/calibration/two_station_20260731.json
```

当前地猛星实时距离候选算法：

```text
每 100 ms 更新一次内部状态
每路保留最近 800 ms
每路至少 3 个有效样本
uR = 右路最低 3 个距离的均值
uL = 左路最低 3 个距离的均值

q_i = ((uR - pR_i) / 1318.28)^2
    + ((uL - pL_i) / 2045.99)^2

w_i = 1 / max(q_i, 0.0004)
distance = clamp(sum(w_i * R_i) / sum(w_i), 800, 3000) mm
```

每次只取四个最近物理点原型。`pR_i、pL_i、R_i` 是由离线程序从原始 JSONL 生成的整数毫米表；地猛星只执行排序、整数平方、加权和与质量门判断，电脑不参与实时定位。

距离质量门：

```text
HIGH:
  两路样本数 >= 6
  MAD_R、MAD_L <= 50 mm
  左路有 SNR 时 >= -5 dB
  或两路均无 SNR 且同一 key_addr 有效
  abs(uL - uR) <= 300 mm
  最近原型 q <= 0.4
  四近邻真值跨度 <= 400 mm
  连续 3 次距离变化 <= 150 mm

MEDIUM:
  两路样本数 >= 5
  MAD_R、MAD_L <= 100 mm
  左路有 SNR 时 >= -6 dB
  或两路均无 SNR 且同一 key_addr 有效
  abs(uL - uR) <= 500 mm
  四近邻真值跨度 <= 400 mm

REJECT:
  其余情况；包括只缺一路 SNR、缺少 key_addr 或地址不一致
```

`HIGH` 才能参与距离授权，`MEDIUM` 只能显示，`REJECT` 最多保持显示 500 ms，不能保持授权。当前离线物理点整组留出结果约为 `MAE=49 mm、P95=164 mm、最大误差=183 mm`；0.8 s 滚动窗口 P95 约 `177 mm`，仍有持续别名窗口，不能用无条件平滑掩盖。质量为 HIGH 的窗口覆盖约 `23%`，其 P95 约 `112 mm`、最大约 `263 mm`。

为验证厂商标准 `P,<主机地址>,<距离>` 无 SNR 帧，使用同一
2026-07-31 数据只移除 SNR 条件做兼容敏感性回放：`HIGH` 覆盖
`24.00%`、P95 `116.32 mm`、最大 `273.81 mm`，仍满足
`覆盖率>=20%、P95<=120 mm、最大<=300 mm`。这只证明放宽 SNR
条件未破坏今天数据上的误差门，不等于无 SNR 实物链路已经验证。

当前两站角度不作为可信单值：

- 离线最佳点估计约为 `MAE=18.25°、P95=32.87°、最大误差=58.37°`。

v0.1 裸露定位臂、v0.2 的 596 mm 扇区拼壳和缺少完整钥匙操作机构的 v0.3 均已退出首选方案。v0.4 按“单热床、免粘接、快拆维护、可替换控制面板、降低返工成本”重构：

1. **一体底壳**：`268×268×76 mm`，承载主控、电池、背面操作区和三个 UWB 卡匣基准；在 CR-3040D 上单次打印。
2. **一体上盖**：`266×266×17.2 mm`，以外表面贴床、内唇和卡扣朝上的方向打印；与底壳通过定位唇边和四处卡扣连接，不使用胶水。内侧增加 8 根 `4×2.4 mm` 径向加强筋，并与支撑柱保留至少 `1 mm` 参数净距。
3. **三枚 UWB 快拆卡匣**：统一 `33×23×8 mm` 滑入式结构，A1/A2/A3 名义等高；接口方向和天线禁布区实测后只需局部修订卡匣。
4. **背面服务面**：`84×64 mm` 独立面板，安装 1.77 英寸 ST7735S、4 位拨码、红绿锁态 LED、迎宾 LED 和调试口；面板具有真实 FRONT 标记，操作面位于 `Y=-126 mm` 的 BACK 侧。
5. **显示压框**：适配 ST7735S PCB `56×34 mm`、名义可视区 `38.5×32 mm`、孔距 `52×30 mm`、孔径 `2.5 mm`；采用 M2.5 间隙孔背面固定。
6. **拨码固定笼**：适配 `12.5×11.72×9.5 mm` 4 位拨码，使用两枚 M2.5 螺钉固定；面板永久标出从左到右 `bit3 → bit0`，`ON` 朝向显示器，并给操作口四周各保留 `3 mm` 余量。
7. **数字钥匙**：名义包络 `105×58×33 mm`，由底壳、上盖、`66×34 mm` 可替换控制面板、捕获式启动按键帽、拨动滑块和电池卡扣组成；启动按键、状态 LED 和拨动槽均为真实贯通结构，包含 KEY REF、503040 电池和 UWB/电源板分区。
8. **钥匙控制与内部布局**：暂为 `50×20×1.6 mm` 控制板预留导轨，启动按键名义行程 `0.8 mm`、拨动滑块名义行程 `8 mm`。503040 电池、电源板和 UWB 的中心 X 分别为 `-26.5、8.5、35 mm`，占位检查要求相邻部件至少 `1 mm` 净距；这些仍需实物板卡、线束和开关复核。

参数源位于 [CAD 目录](../结构设计/C题数字钥匙门锁/cad/README.md)，输出位于 `生成内容/3D打印/C题/v0.4/`。当前 13 种 STL、16 个打印实例均通过重载闭合检查，CAD 回归测试 24/24 通过；钥匙 `105×58×33 mm`、门锁 `Ø276×100 mm` 均位于官方包络内。

旧版聚合 3MF 和跨盘自动排布已经停用。当前脚本先给每个实例写入确定性 XY 变换，按 `7 mm` brim 加 `2 mm` 净距检查边界，再关闭自动排布并逐盘切片。完整 G-code 和首层验证 G-code 均通过 `1 + 1 + 14` 个唯一对象核对；命名对象与包含 brim 的实际首层足迹重叠数均为 `0`，未归属首层挤出数为 `0`。三盘首层实际范围分别为 `9.361～290.639 mm`、`10.361～289.639 mm`、X `6.208～293.792 mm`/Y `40.858～259.142 mm`。喷嘴 `220/255/250 ℃` 和热床 `90/85 ℃` 均通过材料标签范围检查。

2026-07-29 的既有 v0.3 第 3 盘试打曾因床面残留胶层/薄膜、卷曲和喷嘴触碰中止；用户移除残留层后现场反馈打印机恢复正常。v0.4 尚未取得首层完成、整盘完成或尺寸复测记录。
